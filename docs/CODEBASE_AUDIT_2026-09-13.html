4.5 / 10

Verdict: well structured, but not yet safe with student work

The architecture is sensible and the code is readable. It has a TypeScript compiler, a Rust interpreter compiled to WASM and run in a worker, pure workspace reducers, and a Convex backend that never trusts a client-supplied id. Every local gate passes, and the i18n migration is clean.

The score is low because of what happens to user work. A single failed request can overwrite a user's cloud workspace. On a shared browser, one account's code can be uploaded into another account. Up to five minutes of typing lives only in memory. The interpreter gives silently wrong answers on textbook recursion. The compiler rejects a textbook IF/ELSE function. None of these paths is tested, and there is no CI to catch regressions.

What to fix first

This order puts user impact first and effort second. Items 1 to 4 are each a small, contained change.

  1. Stop the two data-integrity bugs. In loadWorkspace, only upload the local copy after a confirmed 200 {workspace:null}, never after an error (WS-1). Key the IndexedDB cache by Clerk user id and clear it on sign-out (WS-2).
  2. Persist typing quickly. Write to IndexedDB about 500 ms after typing stops, and keep the long timer only for cloud uploads. Flush on pagehide and visibilitychange. Store a dirty flag so a newer local copy isn't replaced by an older cloud one (WS-3, WS-4).
  3. Fix interpreter scoping and crashes. Make DECLARE insert into the innermost scope (RT-2). Add a call-depth limit, and re-create the worker after any RUN500 or failed load (RT-1, RT-5).
  4. Fix the compiler's false rejections. Check that every path returns (COMP-1). Accept CHAR where STRING is expected (COMP-3). Use one scope per routine to match the runtime (COMP-2).
  5. Stop the flowchart from corrupting code. Until round-trips are exact, don't write generated code back automatically. Use the stored loopBodyHandle, and ask before Clear Canvas (UI-1, UI-2, UI-6).
  6. Add one CI workflow. It should run typecheck (including convex/), lint with zero warnings, vitest, cargo test and clippy, and rebuild the WASM and diff it against the committed binary (BLD-1, BLD-2, BLD-5).
  7. Turn the audit repros into regression tests. Compile every manual example as a fixture. Run end-to-end compile-then-run tests on the recursion, scoping and nested-loop cases. Add convex-test authorization tests.
  8. Make published claims true. Add the PIPL consent checkbox or reword the sentence (WEB-2). Verify the deletion setup (WEB-3). Correct the CSP and repo-visibility statements (SEC-7). Commit .env.example, fix the MIT/GPL mismatch, and delete apps/web/scripts/deploy.sh.
  9. Accessibility pass. Use native <dialog>, inert on hidden views, a roving-tabindex file tree, AA contrast for --text3, and layout chosen by viewport rather than user agent.
  10. Split the three large files as you touch them: app/page.tsx (2,569 lines), packages/workspace/src/index.ts (2,468) and flowchart/model.ts (1,776).

How the application works

Compile and run

  1. Monaco, or the beta React Flow flowchart, edits the pseudocode source.
  2. compiler.worker.ts runs @pseudobuild/compiler, which tokenizes, parses and checks the source. A 40-entry cache and a stale-request check sit in front of it. It returns diagnostics and the AST as JSON.
  3. wasmRuntime.worker.ts passes the AST JSON to the Rust tree-walking interpreter in lib.rs. Each run has a budget of 1M steps and a 12 s kill timer.
  4. INPUT works by replay. The runtime stops when it runs out of input lines, the UI asks for one, and the whole program re-runs with the lines collected so far.

The only contract between compiler and runtime is matching string keys. Rust reads untyped serde_json::Value and silently ignores node kinds it doesn't know.

Persist and sync

  1. useWorkspaceSession applies pure reducers from @pseudobuild/workspace.
  2. storage.ts writes the whole state to IndexedDB under one key, "current".
  3. Signed in: a full PUT /api/workspace. The route verifies the Clerk token, validates the payload, and calls workspaces.saveCurrent with the user's own JWT.
  4. Convex stores one 512 KB JSON row per Clerk subject. A Svix-verified webhook deletes the rows on user.deleted.

Signed out on the website means memory only. Localhost uses IndexedDB. Signed in means cloud. The browser never talks to Convex directly.

Workspace state and sync · 4/10 · 2 critical, 3 high, 5 medium, 5 low
WS-1CriticalA failed cloud load overwrites the user's cloud workspacelead verified
apps/web/src/lib/storage.ts:61-72, 170-185 · convex/workspaces.ts:229-234

loadWorkspaceFromCloud returns null for any non-OK response and for any thrown error. loadWorkspace reads null as "this account has no workspace" and uploads the local IndexedDB copy with saveWorkspaceToCloud. A scratch test showed the damage. When the GET returned 500, the PUT sent a week-old cache. On a new device with a network error, the PUT sent an empty workspace. Convex's readStoredWorkspace also returns null for stored JSON that fails to parse, which triggers the same path.

Fix. Upload the local copy only after a confirmed 200 {workspace:null}, and only if that copy belongs to the same user. On any other failure, show an error and don't write. Make Convex return a distinct "corrupt" state.

WS-2CriticalOn a shared browser, one account's code is uploaded into another accountlead verified
apps/web/src/lib/storage.ts:8, 67-68, 180-181

Every account shares one IndexedDB key, "current", and no code path clears it. User A's cloud workspace gets cached locally. A signs out, and user B, who has no cloud workspace, signs in. B's GET returns null, so B loads A's cache and PUTs it with B's token. Scratch output: B sees: USER A PRIVATE CODE | PUT auth: Bearer token-B | PUT body: USER A PRIVATE CODE. A school computer lab is the obvious place this happens.

Fix. Key the cache by Clerk user id (current:<userId>), delete it on sign-out, and never upload a cache owned by someone else.

WS-3HighUp to 5 minutes of typing (configurable to 60) exists only in memorylead verified
apps/web/src/app/hooks/useWorkspaceSession.ts:167-177, 255-261 · app/[locale]/app/page.tsx:97, 508

Typing waits for the autosave timer, whose default is 5 minutes. The effect cleanup clears the timer without saving first. Nothing saves on pagehide, visibilitychange or unmount. The only unload hook is a beforeunload prompt. A crash, a mobile tab eviction or a sign-out loses the edits, even in local mode. This makes RT-1 worse, because the only way to recover from RT-1 is a reload, and a reload throws those edits away.

Fix. Write to IndexedDB about 500 ms after typing stops, and use the long interval only for cloud uploads. Flush on cleanup, on pagehide, and when visibilitychange reports hidden.

WS-4HighNewer local work is replaced by the older cloud copy after a failed save
apps/web/src/lib/storage.ts:87-92, 180-181 · useWorkspaceSession.ts:213-216

When a save reaches IndexedDB but the PUT fails (for example a 413), the next load takes the cloud copy (v1) and overwrites IndexedDB (v2). The UI message "Changes remain on this device" is therefore wrong. If the IndexedDB write fails first (QuotaExceededError), the cloud upload is never tried.

Fix. Store a dirty flag and a revision with the local copy. On load, prefer a dirty local copy that is newer, or ask the user. Try the upload even when the local write fails.

WS-5HighSaves can land out of order, and nothing detects conflicts
useWorkspaceSession.ts:196-208 · convex/workspaces.ts:312-318

saveRequestIdRef only protects UI state. The requests themselves are not serialized. In a repro, a slow older save finished after a newer one, and the cloud kept the older state. saveCurrent patches with no revision check, and tabs don't coordinate. Folder toggles, file switches and compiles each trigger a full save, which makes the race likely.

Fix. Allow one save in flight per client, and send the latest state when it finishes. Pass expectedRevision to saveCurrent and reject a mismatch. Use BroadcastChannel to tell other tabs to reload.

WS-6MediumWork written before signing in is discarded at sign-in
apps/web/src/lib/platform.ts:27-40 · useWorkspaceSession.ts:134-165

Sign-in happens in a Clerk modal, so the page never unloads. When the mode switches from memory to cloud, the hook replaces the guest workspace with the cloud one. "Write code, then sign in to save it" deletes the code.

Fix. Import guest documents into the cloud workspace, for example into a "Guest" folder, or confirm with the user first.

WS-7MediumThe editor never loads if IndexedDB is unavailable
useWorkspaceSession.ts:153-165 · storage.ts:41-49

loadWorkspace(...).then(...) has no catch. With blocked storage or a failed database upgrade, the workspace stays null forever and the promise rejection goes unhandled.

Fix. Catch the error, fall back to an in-memory empty workspace, and show a notice.

WS-8MediumThe payload limits contradict the advertised limits, so large workspaces never synclead verified
packages/workspace/src/index.ts:161-170, 2323-2327

350 documents fail with "too many object fields (3004/3000)", so the advertised maxNodes: 500 can't be reached. 3,200 virtual-file lines fail with "too many array items", although the advertised limit is 5,000. The client never checks before sending, so every autosave fails, and WS-4 then loses the work.

Fix. Set the generic counters from the domain limits. Validate on the client before saving, and name the limit that was hit.

WS-9MediumValidation accepts a broken tree that later crashes or hangs renderinglead verified
packages/workspace/src/index.ts:346-352, 762-771

A node whose parent doesn't exist passes validation, then getNodePath throws. A two-folder parent cycle also passes. Those folders vanish from the tree, and getNodePath on them loops forever. One bad stored record can take down the editor.

WS-15MediumNo tests for the paths that lose data

useWorkspaceSession has no tests. The storage tests cover only a successful upload, and the workspace tests don't touch layout, panels or broken trees. WS-1 through WS-7 all slipped through as a result.

WASM runtime · 4/10 · 0 critical, 2 high, 4 medium, 6 low, 1 info
RT-1HighRecursion around depth 600 crashes the WASM instance, and Run stays broken until reloadlead verified
packages/pseudocode-runtime/src/lib.rs:553-580 · apps/web/src/workers/wasmRuntime.worker.ts:154-161 · apps/web/src/runtime/executeRuntime.ts:85-87

I ran a simple recursive R(N) against the committed binary. Depth 400 printed 400. Depth 600 threw RuntimeError: memory access out of bounds, and after that even OUTPUT "alive" failed with the same error in the same instance. The worker catches the trap and posts an ordinary RUN500 result. The runner resolves it like any other result and never resets the worker, so every later run fails. Reloading is the only fix, and a reload throws away unsaved typing (WS-3).

Fix. Add a call-depth counter in call_user_routine that raises "Recursion too deep" at around 250. Re-create the worker whenever run_pseudocode throws. Optionally raise the WASM stack size.

RT-2HighA DECLARE inside a routine overwrites the outer variable, which breaks recursion with localslead verified
packages/pseudocode-runtime/src/lib.rs:210-230, 593-605

DECLARE goes through assign_name, which writes to the nearest scope that already has the name. A procedure that declares its own X and sets it to 5 changes the global X, and the program prints 5 instead of 1. A recursive Sum(3) with a local variable returns 0 instead of 6. There is no error. The compiler treats these programs as valid.

Fix. Make declare and constant insert into scopes.last_mut(), and let only assignment search outer scopes.

RT-3MediumInteger arithmetic runs through f64 and saturates without an errorlead verified
lib.rs:377-381, 449-451, 896-911

9007199254740992 + 1 prints 9007199254740992. 3037000500 * 3037000500 prints i64::MAX. The literal 9223372036854775807 prints 0, because as_i64().unwrap_or(0) falls back to zero.

Fix. Use checked i64 operations when both operands are integers, and raise a RUN error on overflow. Reject integer literals outside the safe range in the parser.

RT-5MediumOne failed WASM load leaves the runtime dead for the sessionlead verified
wasmRuntime.worker.ts:87-93 · executeRuntime.ts:72-82

runtimeReady keeps the rejected promise forever, and a failed preload only sets the status to "error". Every retry waits on the same rejection.

Fix. Clear runtimeReady when it rejects, and call resetWorker() after a preload failure or a RUN500.

RT-6MediumInvalid INPUT silently becomes a default valuelead verified
lib.rs:880-894

Entering abc and 3.7 for two INTEGER inputs prints 0 0 and reports success. For a BOOLEAN input, anything other than "true" becomes False.

Fix. Raise "Expected INTEGER, got 'abc'", or ask for the input again.

RT-15MediumFew tests on the risky runtime paths

5 Rust tests, 4 WASM integration tests and 2 runner tests. None cover scoping, recursion, INPUT coercion, overflow, deep nesting, trap recovery, timeout reset or preload failure. Fix. Add Rust tests for RT-2, RT-3 and RT-6, and integration tests for RT-1 and COMP-7.

RT-7LowREAL output shows inf and NaN, and 4 / 2 prints 2lead verified

Non-finite results don't raise an error, and a whole-number REAL looks exactly like an INTEGER. Fix. Raise a RUN error on non-finite values, and pick one REAL display format.

RT-8LowDIV and MOD use Euclidean semantics, and DIV(i64::MIN, -1) trapslead verified

DIV(-7,2) gives -4 and MOD(7,-2) gives 1. That matches neither truncating nor flooring division. The overflow case throws unreachable. Fix. Document one rule (truncation matches most syllabi), and use checked_div.

RT-10LowOpening a missing file for READ creates a phantom filelead verified

OPENFILE "missing.txt" FOR READ succeeds and saves an empty missing.txt into the workspace. Reading past the end returns "", and there is no EOF(). Fix. Raise an error on a missing READ, and add EOF() to both the compiler and the runtime.

RT-11LowRANDOM returns the same sequence on every run

A fixed seed at lib.rs:113 probably exists so INPUT replay sees the same values. Games still come out identical every time. Fix. Generate a seed once per Run click and reuse it across the INPUT replays.

RT-12LowA leading blank output line disappears

useWorkspaceSession.ts:548-560 strips a leading \n when it syncs replay output, so OUTPUT "" vanishes. Fix. Return stdout as an array of lines.

RT-13LowUnhandled rejection in the runner, and a latent leak of pending runs

workerPromise.finally(...) creates a promise nobody handles. resetWorker() doesn't reject the other pending entries, whose timers can later kill a newer worker. RT-16InfoThe compiler-runtime contract is implicit

Compiler · 5/10 · 0 critical, 1 high, 6 medium, 8 low
COMP-1HighA function that returns from both IF branches is rejectedlead verified
packages/compiler/src/semantics.ts:193, 324-327, 342
FUNCTION Max(A : INTEGER, B : INTEGER) RETURNS INTEGER
    IF A > B
      THEN
        RETURN A
      ELSE
        RETURN B
    ENDIF
ENDFUNCTION

This fails with SEM011 Function "Max" must contain a RETURN statement, because sawReturn only looks at top-level statements. It is one of the most common exam patterns, and students can't run it.

Fix. Real all-paths-return analysis. IF counts when both branches return, and CASE counts when it has OTHERWISE and every clause returns.

COMP-2MediumThe compiler and the runtime disagree on scope
semantics.ts:245-298 vs lib.rs:593-617

The compiler gives every block its own scope, while the runtime has one scope per routine. A DECLARE X : STRING inside an IF overwrites an outer INTEGER X at runtime, and the program prints 1 where 6 is expected. A variable declared inside an IF and used after it is rejected, even though it would run.

Fix. Use one scope per routine in semantics, which is the Cambridge convention, and report a redeclaration as SEM002.

COMP-3MediumExamples copied from the manual fail to compilelead verified
semantics.ts:57-61, 94-118 · manual/manualContent.en.ts:78-88

OUTPUT LCASE('W'), taken from the manual, fails with SEM018 ... must be STRING, got CHAR. Value <- ROUND(RANDOM() * 6, 0) assigned to an INTEGER fails with SEM003. The manual also says CONSTANT values must be literals, but CONSTANT Max <- 2 + 3 compiles.

Fix. Let CHAR widen to STRING. Decide what type ROUND returns and make the code and the manual agree. Enforce literal-only constants.

COMP-4MediumPrograms that type-check but fail or misbehave at runtime
semantics.ts:250-278, 431-482, 541-551 · parser.ts:665
  • A REAL FOR step compiles, then fails at runtime with FOR STEP cannot be zero. This merges RT-9.
  • A function name used as a value compiles, then fails with "Undeclared identifier".
  • IF "abc" > 5 compiles and silently takes the ELSE branch.
  • CASE labels aren't type-checked, and duplicate or misplaced OTHERWISE clauses compile.
  • ARRAY[10:1], 'ab' as a CHAR, and a CONSTANT used as a loop variable all compile.

Fix. Require INTEGER FOR bounds and steps, check symbol kinds, type-check comparisons and CASE labels, and validate array bounds and CHAR length.

COMP-5MediumOne mistake produces a cascade of misleading diagnostics
index.ts:29-32 · parser.ts:430-437, 704-705, 783-791

DECLARE X : Foo yields five errors. FOR <- 1 TO 3 reports an undeclared iterator called "InvalidIterator". IF X > THEN blames the next line. Semantic analysis still runs on ASTs full of error placeholders. For a teaching tool this is the part students see most.

Fix. Skip semantic errors when there are syntax errors, treat UNKNOWN as compatible, advance past a bad type token, and don't consume keywords in parsePrimary.

COMP-6MediumNo cap on diagnostics, so pasted junk can freeze the tab

255 KB of @ produced 261,120 diagnostics, a 55 MB result posted to the main thread for Monaco markers. Fix. Merge runs of bad characters into one diagnostic, and cap the total at about 200.

COMP-14MediumFive tests for the whole compiler

Semantics has 40.8% line coverage. There are no tokenizer, precedence, CASE, RETURN-path, diagnostic-position or limit tests, and no fixtures from the manual, which would have caught COMP-1 and COMP-3. Fix. A table-driven suite that compiles every manual example, plus end-to-end compile-and-run checks.

COMP-7LowThe runtime rejects ASTs the compiler accepts, because of serde's depth limitlead verified

serde_json allows 128 levels of nesting, and the parser allows 200. A 130-term 1+1+... expression compiles, then fails with RUN500 Invalid AST JSON: recursion limit exceeded. This merges RT-4. Fix. Limit AST depth in the compiler to what the runtime accepts, or use serde_stacker.

COMP-8LowDeep unary chains bypass the nesting guard

parseUnary (parser.ts:635-659) recurses without enterNesting. 100k minus signs overflow the stack. The callers catch the error, so the result is a bad message rather than a crash. Fix. Parse prefix operators in a loop.

COMP-9LowNested routine definitions parse but can never be called

Only top-level routines are hoisted, so a PROCEDURE defined inside an IF gives "Unknown procedure". Fix. Report a syntax error for routines that aren't at top level.

COMP-10LowOTHERWISE : and multi-line CASE clauses are rejected

Both forms appear in Cambridge teaching material (parser.ts:295-327). Fix. Accept an optional colon after OTHERWISE, and allow clause bodies to span lines.

COMP-11LowMisleading message when an identifier matches a keyword

DECLARE Length : INTEGER reports that the keyword LENGTH must be uppercase, followed by cascading errors. Fix. Say that Length is a reserved word.

COMP-12LowTokenizer edge cases

IF A<-1 is read as an assignment, and typographic quotes pasted from a PDF are rejected. MAX_SOURCE_BYTES counts UTF-16 units instead of bytes. End columns are sometimes exclusive and sometimes inclusive. Fix. Handle each case individually.

COMP-13Low-2 ^ 2 evaluates to 4

Unary minus binds tighter than ^. All other precedence and associativity checks passed. Fix. Give unary minus lower precedence than ^.

COMP-15LowAn export points at a file that doesn't exist, plus dead code

What is already good

Architecture and security

  • Both public Convex functions take identity from the verified JWT. No function accepts a user or document id, and the token is checked twice, once in the route and again in Convex.
  • The Clerk webhook verifies its Svix signature against the raw body, and deletion runs through an internal mutation.
  • No .env, keyless or Clerk file appears anywhere in git history, and NEXT_PUBLIC_ exposes only public values.
  • HSTS preload, frame-ancestors 'none', nosniff, and no-store on authenticated GETs.
  • Payload limits are enforced at several layers: bytes, nesting depth, entry and node counts, and schema.

Engineering

  • User code compiles and runs in workers. A step budget stops infinite loops in about 70 ms with a line-numbered RUN408.
  • The parser always makes progress. No agent found an input that hangs it, and 228 KB of real code compiles in 34 ms.
  • The workspace reducers are pure and never mutate state. Saved data is versioned, with a v1 to v2 migration, and unknown future versions are rejected.
  • The Monaco integration is careful: no hydration mismatches, a documented iOS workaround, and a tested null-caret guard.
  • The i18n migration keeps English URLs unchanged, permanently redirects /en/*, enforces key parity with Dictionary = typeof en, and emits full hreflang tags and sitemap entries.
  • strict TypeScript everywhere, and a single React and Next resolution. All gates pass in under 30 seconds.
